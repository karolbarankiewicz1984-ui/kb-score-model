# Zasady trwałej pamięci projektu

Celem tego repozytorium jest ochrona KB Score przed utratą ważnych ustaleń wynikającą z długich rozmów lub rozpoczęcia nowego wątku.

## Reguły

1. Istotna zmiana modelu nie powinna pozostać wyłącznie w czacie.
2. Każda zatwierdzona zmiana powinna mieć:
   - datę,
   - opis,
   - powód,
   - checkpoint lub dowody,
   - informację od kiedy obowiązuje.
3. Stare wersje i historia zmian nie są kasowane.
4. Dane obserwacyjne i wyniki pozostają w rejestrze danych; GitHub opisuje logikę i wersje modelu.
5. GitHub nie może być pojedynczym punktem awarii dla raportu 11:30.
6. Po każdej większej korekcie powinien powstać nowy snapshot dokumentacji.
7. Przed wykorzystaniem zmiany w kolejnych analizach należy sprawdzić aktualny stan dokumentacji i Parametry.
8. Nie dokonujemy automatycznej zmiany metodologii po pojedynczym wyniku.
