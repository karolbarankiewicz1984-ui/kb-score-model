# MM-05: private one-button sync (deployment not yet activated)

Architecture: existing GitHub artifacts → local/trusted private publisher → private R2 object → HTTPS Worker with Cloudflare Access → PWA / IndexedDB. No always-on server; no provider requests at download; no public data release. The public engine repository must not contain bundles, credentials, or publisher logs containing records. The Worker has no write endpoint. The PWA never receives a GitHub, R2, or sports API credential.

## Required one-time owner setup (not performed by this PR)
1. Owner chooses a trusted hostname under their Cloudflare account; enable Access for the **whole dedicated origin**, not just /api. Allow only the owner's email and require an appropriate identity provider / MFA. Do not create a bypass policy. Choose session expiry. R2 may require billing activation even within free allowances; review costs and limits before enabling. Confirm provider terms permit private storage of the snapshots.
2. Create a dedicated R2 Standard bucket. Disable r2.dev/public custom domains; do not use an existing public bucket. Set a bucket-scoped object read/write token for publisher only. Store it in the trusted operator environment or private CI secrets; never paste into chat or commit. No extra public Actions artifact with the bundle.
3. In panel/: npm install; npm test; npm run build. Copy wrangler.example.jsonc to ignored wrangler.jsonc. Set APP_ORIGIN, ACCESS_ISSUER (team domain), ACCESS_AUD (application audience), private bucket name and matching custom domain. Set OWNER_EMAIL as Worker secret (`npx wrangler secret put OWNER_EMAIL`); authenticate Wrangler in the account. Deploy with a reviewed Wrangler version. workers_dev and preview_urls must stay false; run_worker_first true. Do not reuse a public or shared origin. No production credentials in Vite env.
4. Before publishing any private data, test unauthorized GET / and /api/panel/latest (must not expose body), expired session, wrong owner, correct owner, public bucket URLs disabled, no CDN caching, app shell and service worker, login navigation. Test with synthetic bundle first. Confirm no cache rule overrides no-store. First load and installation need HTTPS. Cache shell/IndexedDB intentionally remains offline after login; revocation does not remotely erase a previously downloaded snapshot. Use device lock and "Usuń lokalne dane"; no app-level encryption.
5. Run from repo root on trusted operator machine:
```
python -m tools.panel_prepare --day YYYY-MM-DD --abc-run ABC_ID --odds-run ODDS_ID --audit-run AUDIT_ID --out /private/panel.zip
python -m tools.panel_publish /private/panel.zip
# Only after owner authorizes and storage is verified:
python -m tools.panel_publish /private/panel.zip --publish-private
```
Requires authenticated gh CLI with Actions read, Python, and boto3 supporting PutObject IfMatch/IfNoneMatch. Set MM_R2_ACCOUNT_ID, MM_R2_BUCKET, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY securely in environment. Explicit successful run IDs are checked against exact workflow/branch/artifact name; exporter verifies cutoff and source queue. Current code is manual publisher tooling; scheduling/automatic selection is not enabled. No additional calls to sports data APIs.
6. Open authenticated app on Android, install PWA, press "Pobierz dane". On expired session open "Zaloguj / sprawdź sesję" and retry. Import ZIP remains available. Client reads only fixed same-origin HTTPS path and validates response headers, size, SHA-256, schema and timestamps before transactional save. Prior snapshot remains on errors. Server refuses unknown origin, unsigned or expired JWT, wrong issuer/audience/email, arbitrary keys or writes. Server-side publication verifies both timestamps and uses conditional write on exact prior ETag; concurrent conflict must be investigated, never silently retried. Identical payload and cutoffs = no write.
7. Future scheduling: provision a private runner/repository only after setup, approved retention and trusted source selection; never add live publication credentials to public pull_request CI. No cloud resources or paid services are activated by this change.
